# Careeriz – Candidate-side QA report (production, 21–22 Oct 2026)

Tested live on https://www.careeriz.com with a real browser (Playwright / Chrome), logged in as a candidate
(`kunal.shetty02@gmail.com`). Desktop 1366 px and phone 390 px. Every bug listed as fixed was re-tested on the deployed build.

## Summary
- 20 bugs found, 20 fixed and deployed (`67fc8c4`, `d8c3037`, `91a51ec`, `3f0f35a`).
- Second round (two candidate accounts, `kunal.shetty02` and `vinu842`): apply, connect/accept, feed post/like/share,
  count-only notifications, two-way messaging all PASS. Submit application now completes in about 3 s (was 8.4 s).
- Not tested (needs recruiter login / data): recruiter-side ATS (stages, interviews, offers), Google sign-in end to end.

## Open items / suggestions
1. **Google sign-in accounts have no site password** until "Forgot password" is used (expected). For test account `vinu842@gmail.com` a password was set directly in the database at the owner's request.
2. **Withdraw has no confirmation step** and no required reason – easy to withdraw by accident.
3. **Re-applying after a withdrawal is blocked** ("already applied"). Decide whether that is intended.
4. **Headline text containing the word "headline"** is silently dropped while the page says "Profile saved".
5. **Backend logs an error line for every "no profile photo" request** – noisy; lower to a debug log.
6. **SMTP is slow (several seconds per email)**; signup and password-reset still wait for it. Use a background send or SES.
7. **PDF scanning (OCR) is not deployed** – scanned/image-only resumes cannot be parsed on this server.
8. **Login throttling** (10/min) locked out repeated automated logins – expected, but remember it when load-testing.
9. **Test data left on the live site** (account `kunal.shetty02`): edited profile, four resumes, one withdrawn application to "Senior Java Developer", one saved job. Change that password.
